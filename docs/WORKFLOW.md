# Порядок оновлення контенту

## Підготовка текстів

Працюємо в гілці від актуального `main`. `baseline/` зберігає первинний стан, `content/home/` — поточну редакцію. Власник доповнює змістовий бриф; агент готує заміни, пояснення та джерела. У GitHub переглядаємо різницю через pull request.

`python3 tools/check.py` дозволяє незаповнені поля чернетки, перевіряючи всі вже обрані дії. Він також перевіряє контрольні суми 32 файлів вихідного пакета за його оригінальним маніфестом (33 файли разом із маніфестом) й захищені значення робочої копії. Порожні поля не зараховуються як готові рішення.

`python3 tools/check.py --complete` вимагає рішення по кожному ID. Після його проходження агент створює `content/home/READY_FOR_REVIEW`; CI відтоді також вимагає повноти. Якщо робота знову стала незавершеною, прибрати маркер і вказати причину в статусі.

## Схвалення текстів

Власник переглядає зміст, факти та відкриті питання. Схвалення фіксуємо в `content/home/STATUS.md` із посиланням на конкретний commit або PR. Зелений CI і злиття технічної зміни самі по собі не є схваленням маркетингових заяв або дозволом публікувати сайт.

## Внесення в пісочницю

Коли завдання прямо включає внесення, спочатку звірити сайт і сторінку з інвентарем та перечитати актуальні значення. Якщо текст або структура змінилися після знімка, зупинити заміну відповідних полів до узгодження різниці. Не переписувати старий baseline.

Внести схвалені текстові значення зі збереженням сегментів, посилань, структури й поведінки. Перевірити побічний вплив спільних компонентів. Зберегти в репозиторії перелік фактично змінених ID і повторно прочитані значення, щоб відокремити заплановане від внесеного.

## Візуальне приймання

Порівняти однакові ширини: 1383, 820, 667, 393, 320 px. Додатково перевірити 1440 px та межі 991/992, 767/768, 479/480 px; початкові виміри цих додаткових ширин ще не знято.

Перевірити заголовки, CTA, картки, вкладки, всі слайди кейсів, відкриті FAQ, модальні вікна та стани форм без реального відправлення ліда. Без нових обрізань, накладань, зайвих рядків і погіршення читабельності. Не зменшувати шрифт, щоб компенсувати задовгий текст. Початкові оцінки рядків — геометричні, а не підтверджені перенесення в Preview.

Зафіксувати ширину, стан, зміни, результат і знімки. Окремо вказати, хто проводив перевірку: автор змін чи незалежний рев’юер.

## Публікація

Публікація — окреме доручення власника. Перед нею потрібні конкретний сайт, домени, схвалена редакція та завершене приймання. У цьому репозиторії немає автоматичного deploy або publish. Успіх публікації підтверджується окремим результатом Webflow та перевіркою опублікованої сторінки.
