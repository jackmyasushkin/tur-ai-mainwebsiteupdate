# Виправлення анімації порядкових номерів Home — issue #3

Власник погодив стратегію повідомленням **«роби»** після [root cause та плану в issue #3](https://github.com/jackmyasushkin/tur-ai-mainwebsiteupdate/issues/3). Фікс застосовано до draft English Home пісочниці Copy of Tur.ai та перевірено в Designer custom-code Preview. Чинна анімація Finsweet збережена; номери відображаються як `01.–04.`.

## Причина й фактична зміна

Finsweet Number Count перетворює `01` на числове `1` і форматує кожний кадр без доповнення нулем. Вихідні тексти були правильними. Окремий formatter спостерігає лише за чотирма позначеними вузлами та доповнює їхній числовий текст до двох цифр. Перевірка рівності запобігає циклу власних записів; маркер observer на вузлі запобігає повторній ініціалізації. Метрики `62/82/83/3` не позначені й не форматуються.

- Site ID: `6899ffe04a85e00f2b8cf5ab`; Home Page ID: `6899ffe04a85e00f2b8cf5ac`.
- HOME-071/074/077/080: додано лише `data-tur-number-format="ordinal-2"`.
- Оригінальні `fs-numbercount-element="number"`, тексти, крапки, класи, стилі, структура й параметри анімації збережені.
- Скрипт `turaihomeordinalformatterissue3`, версія `1.0.0`, застосований лише в **Home footer**. Повний код: [home-ordinal-format.js](../../webflow/home-ordinal-format.js).
- До/після дерева Home відрізняються тільки чотирма погодженими маркерами. Freeform head/footer Home і freeform код сайту точно збіглися при живому порівнянні. Site-wide registered application відсутня.

## Спосіб підключення

Погоджена логіка й сторінковий обсяг збережені; спосіб підключення адаптовано до фактичних можливостей Webflow. Запис у freeform footer повернув 404, а штатне поле Custom Code у Designer виявилося заблокованим тарифом. Той самий код зареєстровано через підтримуваний Custom Code API. `add_page_script` також повернув 404, оскільки блок застосування ще не існував. [Офіційний upsert](https://developers.webflow.com/data/reference/custom-code/custom-code-pages/upsert-custom-code), доступний як `set_page_scripts`, створив новий Home-only блок. Попередня відсутність блоку підтверджена читанням; чинний freeform код не замінювали.

Перед успішною реєстрацією API відхилив display name з розділовими символами (400); сумісне ім’я `TuraiHomeOrdinalFormatterIssue3` прийнято. Ці помилки не були 429. Відповіді перевіряли за вкладеним результатом, оскільки зовнішній `isError` іноді залишався false навіть за помилки дії. Після кожного невдалого запису фактичний стан перечитано.

У скомпільованому Preview Webflow вбудував точний formatter, прибравши тільки кінцевий перенос рядка. Підключення Finsweet залишилося чинним. План і тариф не змінювали, сайт не публікували.

Повна редакційна перевірка, 21 Python-тест, узгодженість handoff, тест обмежувача темпу, перевірка історичного контентного run і перевірка нового animation run пройшли. Результати: `check-results.json`. Новий Node-тест та перевірка доказів включені до GitHub Actions.

Реальні рендер-кадри записані в ізольованій Chrome fixture. На Home виконано окремі повторні DOM-читання, а не запис кожного відмальованого кадру. Це producer QA; незалежне приймання й перевірку опублікованої версії фіксу не виконували. Попередні межі перевірки форм та інші out-of-scope знахідки контентного перенесення залишаються у його історичному звіті.

Копія fixture та сервер є у `qa/ordinal-animation/`. Сервер слухав лише localhost, його зупинено після QA. Тестову вкладку закрито. Designer повернуто в Design, 1383 px, із вимкненим custom-code Preview.

## Темп і публікація

22 послідовні MCP-виклики, 30 облікованих операцій загалом, максимум **10 операцій у будь-які 60 секунд**, 13 записаних пауз, щонайменше 2 секунди між завершенням виклику й наступним зверненням. **429 не було.** Внутрішня кількість HTTP-запитів MCP та браузерних запитів ресурсів невідома; не прирівнюємо її до цього журналу.

До початку завдання пісочниця вже мала публікацію `2026-10-13T01:53:31.599Z`. Фінальне читання показує те саме `lastPublished`. **Цей run не публікував фікс і не зливав PR.**

## Відновлення

Після повторного читання й перевірки сторонніх змін прибрати тільки Home application скрипту `turaihomeordinalformatterissue3` через `remove_page_script`, зберігши інші scripts, якщо вони з’явилися. Прибрати лише власні чотири `data-tur-number-format` маркери. Оригінальні Number Count атрибути й текстові значення не змінювати. Зареєстрована версія може залишатися незастосованою в каталозі; її наявність сама по собі не запускає код. Результат відновлення — попередня відома поведінка `1–4` після анімації. Публікація відновлення також потребує окремого доручення.
